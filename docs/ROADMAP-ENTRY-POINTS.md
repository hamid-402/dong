# نقطهٔ بازگشت قبل از نقشهٔ ورود

| فیلد | مقدار |
|------|--------|
| نشانهٔ گیت | `baseline/before-entry-roadmap` |
| معنی | یادداشت این نقشه در تاریخچه، و کل درخت کاری در stash همنام |
| تاریخ ثبت | ۱۴۰۵/۰۷/۱۳ (۵ اکتبر ۲۰۲۶) |

برچسب `baseline/before-entry-roadmap` همین سند را در تاریخچه قابل‌جستجو می‌کند. کل کد محصول، همان لحظه، در stash با همین نام است. برچسب به‌تنهایی کدهای تعهدنشده را برنمی‌گرداند.

دیدن stash:

```
git stash list
```

برگرداندن همان درخت، روی وضعیت فعلی:

```
git stash apply "stash^{/baseline/before-entry-roadmap}"
```

## پنج مرحله

۱. **شناخت کارت و شبا.** رقم کنترل کارت، رقم کنترل شبا، پیش‌شمارهٔ بانک. فرم دستور واریز نام بانک را نشان می‌دهد و شمارهٔ خراب را ذخیره نمی‌کند. نامی که کاربر نوشته باشد می‌ماند. دستورهای قبلی باز می‌شوند.

۲. **چسباندن پیامک بانک.** کنار فرم خرج و ثبت تسویه. پیش‌نمایش مبلغ، جهت، تاریخ و کد پیگیری. اعمال فقط فرم را پر می‌کند. متن نامربوط فرم را دست نمی‌زند.

۳. **جریان بدهی و جملهٔ طرف حساب.** همان پیشنهاد تسویهٔ حداقلی، به‌صورت بدهکار / مبلغ / طلبکار، با متن کپی و باز کردن همان اقدام تسویه. روی پیشخوان خانه: بیشترین بدهی یا طلب، با نام طرف. فضای شخصی این جمله را ندارد.

۴. **یک خط توضیح در منوی فضا.** هر مقصد منوی زیر هدر یک خط دوم می‌گیرد. هیچ مقصدی حذف نمی‌شود و هدر و مسیر عوض نمی‌شوند.

۵. **ریز اقلام رسید.** فقط وقتی خواندن رسید در قابلیت‌ها «وصل‌شده» باشد. در حالت آزمایشی فروشنده یا مبلغ به‌عنوان واقعیت نشان داده نمی‌شود.

بیرون از این نقشه: عنوان نقش بسته به نوع فضا، دفتر حساب و استهلاک، دیوار کارت پیشخوان سامانهٔ مقایسه‌ای، و نشان وضعیت ساختگی.
