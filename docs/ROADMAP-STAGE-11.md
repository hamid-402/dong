## ۳. برش‌های اجرایی

هر برش کامل تحویل می‌شود: `contracts` → مهاجرت DB → store حافظه و Postgres → API → UI → تست → سند → `capabilities` صادق. هیچ برشی نیمه‌کاره رها نمی‌شود.

**خروجی:** نام‌کاربری یکتا، تلفن E.164، تغییر ایمیل با تأیید مجدد، ورود با نام‌کاربری/تلفن/ایمیل، ترجیح واحد نمایش کاربر، نقش سراسری روی حساب.
**DoD:** ثبت‌نام نام‌کاربری اجباری می‌گیرد · نام‌کاربری تکراری ۴۰۹ می‌دهد · تغییر ایمیل رمز فعلی می‌خواهد و `emailVerified` را صفر می‌کند · تلفن هرگز «تأییدشده» نشان داده نمی‌شود · حساب‌های موجود بدون نام‌کاربری کار می‌کنند و در اولین ورود درخواست انتخاب می‌شود.

**DoD:** فیش تأییدنشده **هیچ** تأثیری بر بدهی ندارد · تأیید فیش ژورنال دوطرفه می‌سازد · پرداخت موفق درگاه با verify واقعی تسویه را confirm می‌کند · تنخواه مانده منفی نمی‌گیرد · خرید اعتباری تا تسویه در بدهی گروه می‌ماند · هیچ دکمهٔ پرداخت بدون endpoint فعال نمایش داده نمی‌شود؛ نبود کلید درگاه در `capabilities` به‌عنوان `stub` گزارش می‌شود · **پرداخت به‌جای (on-behalf):** `POST .../payments/on-behalf` با تأیید مالی یا پرداخت‌کننده · بدهکار برای مبالغ بالای سقف maker-checker خودتأیید نمی‌کند · تا تأیید ژورنال ساخته نمی‌شود · پس از تأیید ژورنال `payment_on_behalf` (و در صورت تسویهٔ لینک‌شده، confirm + انتقال اعتبار به پرداخت‌کننده) · `providers.paymentOnBehalf=on_behalf_v1`.
**پیشرفت:** انجام شد — فیش/تنخواه/اعتباری + مهاجرت `0058` جدول `payment_on_behalf` · Memory+Postgres · endpoints list/create/approve/reject · UI فرم + صف تأیید · تست‌های deny / journal / amount mismatch / unapproved.

## ۵. قواعد ثابت کل مرحله

1. مبلغ‌ها همیشه `IRR minor` ذخیره می‌شوند؛ فقط لایهٔ نمایش واحد دارد.
2. هیچ قابلیت قدیمی حذف نمی‌شود؛ مسیرهای سازگاری (`CLASSIC_REDIRECT_PATHS`) حفظ می‌شوند.
3. هر قابلیت جدید در `GET /system/capabilities` با نام صادق اعلام می‌شود؛ نبود سرویس بیرونی `stub` گزارش می‌شود.
4. شمارهٔ تلفن خام مخاطبین ذخیره نمی‌شود؛ فقط هش با pepper سرور.
5. هیچ دکمه/برچسب/آمار بدون منبع runtime واقعی ساخته نمی‌شود.
6. هر جدول جدید هم store حافظه و هم Postgres دارد تا اجرای بدون DB نشکند.
7. هر endpoint جدید: طرح Zod، کلید idempotency روی create، rate limit در مسیرهای حساس، رکورد audit.
