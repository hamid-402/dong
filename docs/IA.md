# معماری اطلاعات (IA) — دنگ همکاری

وضعیت: اجرایی (بازطراحی UX مسیر مشتری — سپتامبر ۲۰۲۶)

## قانون طلایی

هیچ قابلیت، route، منو یا دکمه حذف نمی‌شود. فقط سلسله‌مراتب شفاف می‌شود (Primary / Secondary / More).

## مدل ذهنی

کاربر همیشه در یکی از این سه زمینه است:

| زمینه | ریشه | کار اصلی (Primary) |
|--------|------|---------------------|
| شخصی | `/hub/~me` یا تب «من» | ثبت خرج خصوصی |
| گروه | `/hub/~group` یا تب «گروه» | ثبت خرج گروهی + مانده |
| سازمان | `/hub/~orgs` یا تب «سازمان» | ثبت/تأیید خرج شرکتی + بودجه |

لایهٔ سراسری: workspace switcher، اعلان، پروفایل، یافتن (داخل «همه ابزارها»).

## Chrome

- **یک ردیف تب** (موبایل: dock · دسکتاپ: header): `خانه · زمینهٔ فعال · خرج‌ها · بیشتر`
- آیتم‌های قبلی (خرید، مدیریت، من/گروه جدا، …) از تب More، پوشه‌ها، یا «همه ابزارها» reachable می‌مانند.
- منوی classic `AppShell` از همان `buildNavForTemplate` / `classicNavForTemplate` تغذیه می‌شود.

## خانهٔ هاب (`/hub`)

پیش‌فرض (لاغر):

1. سلام + تاریخ
2. یک CTA اصلی زمینه‌ای + میانبرهای ثانویه
3. راهنمای سفر زمینه‌ای (از workspace واقعی)
4. فعالیت اخیر (۳ مورد)

جمع‌شوندهٔ **«همه ابزارها»** (بدون حذف):

- Hero، یافتن، strip مالیه من، شبکهٔ کامل ماژول‌ها (`RAW_MENU_ITEMS` فیلترشده)

## مسیر canonical

| کار | URL |
|-----|-----|
| هاب | `/hub` |
| شخصی | `/hub/~me` (یا `/hub/spaces/~me`) |
| گروه | `/hub/~group` |
| سازمان‌ها | `/hub/~orgs` |
| مالی workspace | `/hub/finance/~workspaces` |
| دفتر روزانه | `/hub/~daily-ledger` |
| پیشنهادها | `/hub/~proposals` |
| پروفایل | `/hub/~profile` |
| بیشتر / مدیریت | `/hub/manage` |

مسیرهای classic با redirect به hub حفظ می‌شوند.

## سفرهای مشتری

### A — گروه دوستان
ورود → خانه (CTA ثبت خرج) → گروه → مانده بالا + ثبت سریع → تسویه از همان صفحه / مالی

### B — شخصی
ورود → تب من / CTA خصوصی → فرم ثبت سریع → منابع و گزارش پایین‌تر

### C — سازمان
ورود → خانه سازمان → بودجه و مطالبات → خرج/تأیید؛ خرید از تدارکات (ثانویه / More)

## قوانین ناوبری

1. هر صفحه حداکثر یک CTA رقابتی در viewport اول.
2. Quick actions و header actions: Primary + Secondary (همه لینک‌های قبلی می‌مانند).
3. ماژول خرید/اموال فقط وقتی template اجازه دهد (فیلتر موجود).
4. در حالت content: «در این پوشه» به‌جای ریل ثابت هم‌سطح.
5. یافتن فقط از دادهٔ API — بدون نتیجهٔ جعلی.
