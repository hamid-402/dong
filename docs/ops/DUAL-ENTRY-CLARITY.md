# شفاف‌سازی دو مسیر ثبت پول (`dual-entry-clarity`)

وضعیت: **D0–D4 + hardening اجرا شده** · فقط additive  
قوانین: no-fake-data · یک هستهٔ مالی · بدون حذف route/API · بدون ادغام اجباری UI

### Hardening پس از ممیزی (همان جلسه)

- `MoneyEntryChooser` بیرون از `<details>` در خانهٔ فضا؛ نقش فقط‌خواندنی مخفی
- HomeMoneyCommand: یک primary «ثبت پول» → `/record`؛ دفتر فقط برای غیرشخصی
- Command palette: دو شغل با haystack
- `?from=ledger` بنر برگشت در فرم خرج
- Empty-day + overview علامت `relatedExpenses`
- Onboard دفتر + برچسب «ورود از جدول»
- Entry CTAs گروه/شخصی/هاب/تور/بریفینگ → `/record` یا «ثبت پول»
- i18n shell/tour/statements هم‌راستا با ثبت پول

## حکم محصول

دو مسیر می‌مانند. مشکل «تکرار» نیست؛ **ابهام شغل** و **تقارن دید ناقص** است.

| مسیر | شغل (JTBD) | نام پیشنهادی در UI | Route |
|------|------------|-------------------|-------|
| A | خرج رویدادمحور با تقسیم/تأیید/سیاست | **خرج کامل** (فهرست: «خرج‌ها») | `/expenses` |
| B | مصرف تکراری روز×عضو / Dong-To | **ثبت روزانه** (فهرست: «دفتر روزانه») | `/ledger` |

هسته: همان `finance.expense` + journal · B با `source=daily_ledger` · A بدون source (یا `expense`).

---

## اصول طراحی (رو به جلو)

1. **Additive:** هیچ route/API/قابلیتی حذف نمی‌شود؛ فقط برچسب، راهنما، لینک متقابل، و سطح دید اضافه می‌شود.
2. **یک حقیقت پولی:** مانده/تسویه/صورتحساب همهٔ منابع را می‌بینند (مثل امروز).
3. **بدون عدد جعلی:** هر ردیف «مرتبط» در ماتریس یا لیست از API واقعی می‌آید.
4. **یک primary در هر سطح:** در خانهٔ فضا حداکثر یک CTA غالب برای «ثبت پول» که به **انتخابگر شغل** می‌رود؛ نه دو دکمهٔ هم‌وزن مبهم.
5. **Persona-aware:** مهمان/ناظر بدون CTAی ۴۰۳؛ همان نقش‌گیت فعلی.

---

## مدل ذهنی کاربر (یک جمله)

> پول گروه یک‌جاست؛ **ثبت روزانه** برای تیک‌های روزمره است، **خرج کامل** برای خرج‌هایی که تقسیم و جزئیات می‌خواهند. هر دو در مانده و فهرست خرج دیده می‌شوند؛ ویرایش هر کدام از مسیر خودش.

## لایهٔ ۱ — شفاف‌سازی نام و کپی

### برچسب‌ها (fa.json / NAV_LABELS)

| کلید | امروز | پیشنهاد |
|------|-------|---------|
| `nav.addExpense` | ثبت خرج | **ثبت پول** (ورودی انتخابگر) یا نگه داشتن + زیرعنوان |
| CTA به expenses | ثبت خرج | **خرج کامل** |
| CTA به ledger | دفتر روزانه | **ثبت روزانه** |
| `nav.expenses` | خرج‌ها | خرج‌ها (فهرست همه) |
| `nav.ledger` | دفتر روزانه | دفتر روزانه |

توضیح یک‌خطی صفحه:

- `/expenses`: «خرج با تقسیم، تأیید و جزئیات — برای رویدادها و موارد غیرروزمره.»
- `/ledger`: «ماتریس روز×عضو برای مصرف تکراری — تیک کاتالوگ و Dong-To.»

کپی متقابل (هر صفحه لینک به دیگری با جملهٔ صادق):

- در فرم خرج: «مصرف روزانهٔ تکراری؟ از ثبت روزانه سریع‌تر است.» → `/ledger`
- در دفتر: «تقسیم پیچیده یا چندپرداخت‌کننده؟ از خرج کامل.» → `/expenses#…`

## لایهٔ ۲ — انتخابگر شغل در خانهٔ فضا (`MoneyEntryChooser`)

جایگاه: زیر `HomeMoneyCommand` / به‌جای دو دکمهٔ هم‌سطح «ثبت خرج» و «دفتر روزانه».

```
┌─────────────────────────────────────────────┐
│ امروز چطور ثبت می‌کنی؟                       │
│                                             │
│ ┌─────────────────┐  ┌─────────────────┐   │
│ │ ثبت روزانه      │  │ خرج کامل         │   │
│ │ تیک روز×عضو     │  │ تقسیم و جزئیات   │   │
│ │ → /ledger       │  │ → /expenses      │   │
│ └─────────────────┘  └─────────────────┘   │
│ نکته: هر دو در مانده و فهرست خرج می‌آیند.   │
└─────────────────────────────────────────────┘
```

قواعد:

- فقط وقتی `!isReadOnlyRole` و فضا غیرشخصی (یا شخصی فقط «خرج کامل» اگر ledger مخفی است).
- برای building/org: زیرعنوان اختیاری «شارژ واحد» روی خرج کامل اگر `expenseHrefForUnit` در scope باشد (additive).
- FAB موبایل: همان انتخابگر (sheet) به‌جای پرش مستقیم به expenses — مگر persona فقط یک مسیر مجاز داشته باشد.

## لایهٔ ۳ — تقارن دید (بدون تغییر معنایی source)

### ۳‑الف) فهرست خرج‌ها (`/expenses`)
- Badge صادق روی ردیف: «روزانه» اگر `source === 'daily_ledger'`.
- اکشن موجود حفظ: ویرایش خطوط روزانه از مسیر دفتر (کپی فعلی تقویت شود).

### ۳‑ب) دفتر روزانه (`/ledger`) — **مرتبط‌های همان روز (فقط‌خواندنی)**
- API additive: مثلاً در پاسخ `GET …/daily-ledger` فیلد اختیاری  
  `relatedExpenses?: { id, title, amountMinor, href }[]`  
  فقط خرج‌های **همان روز** با `source !== 'daily_ledger'` (یا null).
- UI: نوار/سکشن «خرج‌های کامل همین روز» — لینک به جزئیات در `/expenses`؛ **بدون ویرایش از ماتریس**.
- اگر خالی: سکشن نشان داده نمی‌شود (no-fake-empty).

این حس «دو دفتر» را می‌شکند بدون ادغام write-path.

---

## لایهٔ ۴ — ارتقای حرفه‌ای مسیر A (خرج کامل)

Additive روی فرم/لیست موجود:

1. **Stepper واضح‌تر:** مرحلهٔ «نوع ثبت» فقط لینک به روزانه (نه duplicate form).
2. **پیش‌فرض هوشمند نرم:** اگر کاربر از ledger آمده با query `?from=ledger`، بنر «برگشت به ثبت روزانه».
3. **خلاصهٔ قبل از ثبت:** جمع سهم‌ها / zero-sum (اگر الان ناقص است، کامل شود — بدون تغییر قرارداد مگر additive).
4. **خالی‌حالت:** «برای ناهار تکراری گروه، ثبت روزانه سریع‌تر است» + CTA.
5. **لیست:** فیلتر اختیاری «همه / فقط روزانه / بدون روزانه» از query موجود یا جدید — پیش‌فرض همه.

---

## لایهٔ ۵ — ارتقای حرفه‌ای مسیر B (ثبت روزانه)

Additive روی ماتریس موجود:

1. **عنوان شغل:** «ثبت روزانه» در header؛ «دفتر» به‌عنوان ظرف بماند.
2. **راهنمای روز اول:** یک‌بار (ui-prefs) — دو جمله + لینک خرج کامل.
3. **سکشن related expenses** (لایه ۳).
4. **خالی‌حالت روز:** «هنوز تیک روزانه نیست — خرج کامل امروز را پایین ببینید» اگر related داشته باشد.
5. **Import Dong-To:** برچسب «ورود از جدول» زیر عنوان، نه مسیر سوم ذهنی.
6. **موبایل:** حفظ الگوی عضو → تیک (IA موجود)؛ فقط کپی شغل.

---

## لایهٔ ۶ — ناوبری و Finder

- Command palette: دو نتیجه با haystack شغل  
  - «ثبت روزانه · تیک مصرف» → ledger  
  - «خرج کامل · تقسیم» → expenses  
- `GroupOpsRail` / mosaic: hintهای هم‌راستا با جدول نام‌ها.
- تب پایین «خرج‌ها» = فهرست همه (truth)؛ FAB = انتخابگر.
