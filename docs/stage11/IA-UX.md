## ۲. سه فضای ذهنی کاربر

سامانه از دید کاربر سه فضا دارد و ناوبری همین سه را منعکس می‌کند:

```
۱. «من»      /account/*  و  /me/*        هویت، دوستان، مالی شخصی
۲. «گروه»    /w/[slug]/*                 خرج جمعی، کاتالوگ، صورتحساب، پرداخت
۳. «سامانه»  /admin/*                    فقط platform_owner / platform_support
```

قاعده: چیزی که به شخص تعلق دارد هرگز داخل مسیر گروه نمی‌رود و برعکس. «دوستان من» در گروه نیست؛ «کاتالوگ گروه» در حساب من نیست.

## ۳. نقشهٔ کامل مسیرها

### ۳.۱ فضای «من»

| مسیر | عنوان | تب‌های داخلی | برش |
|------|--------|--------------|-----|
| `/account` | حساب من | مشخصات · هویت · واحد نمایش · خروج | S11-01 |
| `/account/security` | امنیت | رمز · نشست‌ها · دومرحله‌ای | موجود |
| `/account/friends` | دوستان | دوستان من · درخواست‌ها · یافتن کاربر · مخاطبین | S11-02 |
| `/account/privacy` | حریم خصوصی | قابلیت یافت‌شدن · بلاک‌شده‌ها · خروجی داده | S11-02 |
| `/me/finance` | مالی من | نمای کلی · درآمد · هزینه · بودجه و هشدار · هدف · تحلیل ماه | S11-10 |

`/account` تبِ «هویت» می‌گیرد که نام‌کاربری، ایمیل و تلفن را یکجا مدیریت می‌کند — سه فرم کوچک با تأیید مستقل، نه یک فرم بزرگ.

### ۳.۲ فضای «گروه» — صفحه‌های موجود (دست‌نخورده)

`home` · `space` · `expenses` · `settlements` · `invoices` · `recurring` · `addons` · `approvals` · `org-finance` · `ledger` · `members` · `procurement` · `proposals` · `assets` · `partners` · `settings` · `audit` · `metrics` · `jobs` · `more`

هیچ‌کدام حذف نمی‌شوند و `CLASSIC_REDIRECT_PATHS` حفظ می‌شود.

### ۳.۳ فضای «گروه» — صفحه‌های جدید

| مسیر | عنوان | تب‌های داخلی | برش |
|------|--------|--------------|-----|
| `/w/[slug]/catalog` | کاتالوگ | اقلام · پرکاربردها · دسته‌ها · تاریخچهٔ قیمت | S11-06 |
| `/w/[slug]/statements` | صورتحساب‌ها | فهرست اعضا · بازهٔ زمانی · دانلود | S11-08 |
| `/w/[slug]/statements/[userId]` | صورتحساب یک عضو | خطوط قلم · جمع · پرداخت | S11-08 |
| `/w/[slug]/statements/[userId]/print` | نسخهٔ چاپی | — (بدون chrome، آمادهٔ PDF) | S11-08 |
| `/w/[slug]/payments` | پرداخت‌ها | فیش‌های در انتظار · تنخواه · خرید اعتباری | S11-09 |
| `/w/[slug]/charts` | نمودارها | خرج · اعضا · دسته · مانده | S11-11 |

### ۳.۴ صفحه‌های جدید داخل صفحه‌های موجود (بدون مسیر جدید)

| قابلیت | کجا می‌نشیند |
|---------|---------------|
| درخواست‌های عضویت | تب جدید در `/w/[slug]/members` |
| افزودن با شناسه / از دوستان | drawer روی `/w/[slug]/members` |
| تغییر نقش و سطح دسترسی | drawer روی سطر عضو در `/w/[slug]/members` |
| انتقال مالکیت | بخش خطر در `/w/[slug]/settings` |
| بازهٔ جانشینی مادرخرج | کارت در `/w/[slug]/members` |
| انتخابگر کاتالوگ | داخل `/w/[slug]/ledger` و فرم خرج |
| واحد نمایش فضا | `/w/[slug]/settings` |

این تصمیم آگاهانه است: ۶ مسیر جدید در برابر ۷ قابلیت که داخل صفحه‌های موجود جا می‌گیرند — تا ناوبری متورم نشود.

### ۳.۵ فضای «سامانه»

| مسیر | عنوان | تب‌های داخلی |
|------|--------|--------------|
| `/admin` | کنسول سامانه | نمای کلی · کاربران · نقش‌ها · پرچم‌ها · سلامت · رویداد امنیتی · break-glass |

فقط برای `platform_owner` و `platform_support` (فقط‌خواندنی). برای بقیه مسیر **وجود ندارد** (۴۰۴، نه ۴۰۳ — تا وجودش لو نرود).

## ۵. الگوی واحد هر صفحه

```
┌──────────────────────────────────────────────────┐
│ breadcrumb: گروه همکاران › کاتالوگ                │
│ ┌───────────────┐              ┌───────────────┐ │
│ │ عنوان صفحه    │              │ اقدام اصلی    │ │  ← دقیقاً یک primary
│ │ یک خط توضیح   │              │ … منوی بیشتر  │ │
│ └───────────────┘              └───────────────┘ │
│ ── نوار تب‌های داخلی (حداکثر ۵) ────────────────  │
│ ── نوار فیلتر/جست‌وجو (اگر فهرست دارد) ─────────  │
│                                                  │
│   محتوا: فهرست یا کارت یا فرم                     │
│                                                  │
│   حالت خالی: چه چیزی نیست + چرا + یک دکمه         │
│   حالت خطا:  چه شد + کد + دکمهٔ تلاش مجدد          │
```

## ۶. جریان‌های کلیدی — کوتاه‌ترین مسیر

### الف) پیدا کردن و دوست شدن — ۳ گام
```
/account/friends → تب «یافتن کاربر» → نام‌کاربری دقیق → «درخواست دوستی»
```
طرف مقابل در زنگ اعلان یک کارت با دو دکمه می‌بیند: پذیرش · رد. تمام.

### ب) ساخت گروه با دوستان — ۴ گام
```
فضا جدید → نام گروه → انتخاب از فهرست دوستان (چک‌باکس) → نقش من: مادرخرج / عضو
```
انتخاب نقش خودم در همان گام آخر و با دو کارت توضیح‌دار، نه یک select گنگ.

### ج) ثبت ناهار روزانه — ۲ کلیک برای هر نفر
```
/w/[slug]/ledger → کارت «امروز»
┌─────────────────────────────────────────────────────┐
│  جمعی (تقسیم مساوی)                                  │
│  ☑ نون   ۲ عدد   ۵۰٫۰۰۰ ریال                        │
│  ☑ پنیر  ۱ بسته  ۲٫۴۵۰٫۰۰۰ ریال                     │
├─────────────────────────────────────────────────────┤
│  فردی (هر کس مال خودش)      نوشابه   ماست           │
│  ساریخانی                      ☑        ☐           │
│  منتظری                        ☐        ☑           │
│  کاظمی                         ☑        ☑           │
│  مرادی                         ☑        ☐           │
│  جلالی                         ☐        ☑           │
├─────────────────────────────────────────────────────┤
│  جمع امروز: ۳٫۴۰۰٫۰۰۰ ریال        [ثبت روز]          │
└─────────────────────────────────────────────────────┘
```
ستون‌های فردی از فهرست «پرکاربردها» می‌آیند. تیک زدن = یک قلم با تعداد ۱. تغییر تعداد با کلیک روی عدد. تایپ آزاد در «افزودن قلم دیگر» باقی می‌ماند.

### د) دیدن و پرداخت بدهی — ۳ گام
```
خانه → کارت «بدهی من: ۶۸۰٫۰۰۰ ریال» → «پرداخت»
   ├─ درگاه پرداخت   → بازگشت موفق → بدهی همان لحظه کم می‌شود
   └─ کارت‌به‌کارت    → مبلغ + تاریخ + شمارهٔ پیگیری + عکس فیش
                        → «در انتظار تأیید مادرخرج» با نشان زرد
                        → پس از تأیید: بدهی کم می‌شود + اعلان
```
تفاوت دو مسیر **قبل از انتخاب** در متن دکمه‌ها توضیح داده می‌شود، نه بعد از آن. فیش تأییدنشده هرگز به‌عنوان «پرداخت‌شده» نشان داده نمی‌شود.

### ه) صورتحساب من — ۲ گام
```
خانه → «صورتحساب من» → بازه (امروز / این دوره / بازهٔ دلخواه)
      → جدول ریز اقلام → [دانلود CSV] [نسخهٔ چاپی]
```

### و) تحلیل آخر ماه — ۱ گام
```
/me/finance → تب «تحلیل ماه»
   درآمد ثبت‌شده  −  هزینهٔ شخصی  −  سهم گروه  =  باقی‌مانده
   نمودار ترکیب دسته + بزرگ‌ترین سه هزینه + وضعیت هدف پس‌انداز
```

## ۷. طراحی کاتالوگ (پرخطرترین صفحه از نظر شلوغی)

سه سطح افشای تدریجی:

| سطح | چه می‌بیند | برای کی |
|-----|-----------|---------|
| **تیک روزانه** | فقط نام + واحد + چک‌باکس | همهٔ اعضا، در دفتر روزانه |
| **فهرست کاتالوگ** | نام · دسته · واحد · قیمت · وضعیت | همهٔ اعضا، در `/catalog` |
| **ویرایش قلم** | + توضیح · SKU · بارکد · تاریخچهٔ قیمت | مادرخرج |

فرم افزودن قلم **سه فیلد** باز می‌شود: نام، واحد، قیمت. بخش تاشو «مشخصات بیشتر» شامل توضیح، دسته، SKU، بارکد.

جست‌وجو: یک فیلد، تطبیق زیررشته روی نام نرمال‌شده، با فیلتر دسته و کلید «فقط فعال‌ها». نتیجهٔ خالی پیشنهاد «افزودن قلم با همین نام» می‌دهد.

غیرفعال‌سازی در برابر حذف: **حذف وجود ندارد**. «غیرفعال» با توضیح «در ثبت‌های جدید نمی‌آید، سوابق دست‌نخورده می‌ماند». این متن روی خود دکمه است، نه در راهنما.

## ۹. حالت خالی، خطا و انتظار

| حالت | متن | اقدام |
|------|-----|--------|
| کاتالوگ خالی | «هنوز قلمی ثبت نشده. اولین کالا یا خدمت را اضافه کنید تا ثبت روزانه سریع شود.» | «افزودن قلم» |
| دوستی ندارد | «هنوز دوستی اضافه نکرده‌اید. با نام‌کاربری دقیق فرد را پیدا کنید.» | «یافتن کاربر» |
| صورتحساب خالی | «در این بازه خرجی برای شما ثبت نشده.» | «تغییر بازه» |
| فیش در انتظار | نشان زرد «در انتظار تأیید مادرخرج» + زمان ثبت | — |
| درگاه بدون کلید | مسیر پرداخت درگاه **پنهان** است؛ در `/settings` توضیح «درگاه تنظیم نشده» | «تنظیم درگاه» (فقط مالک) |
| بدون داده برای نمودار | جعبهٔ خالی با متن «داده‌ای برای این بازه نیست» | «تغییر بازه» |

هیچ حالت خالی‌ای عدد صفر تزئینی یا نمودار جعلی نشان نمی‌دهد.

## ۱۰. اعلان و بازخورد

| رخداد | کانال | متن |
|--------|-------|-----|
| درخواست دوستی | زنگ اعلان + SSE | «فلانی درخواست دوستی فرستاد» |
| درخواست عضویت | زنگ + صف تأیید | «فلانی درخواست عضویت در گروه دارد» |
| فیش ثبت شد | زنگ برای مادرخرج | «فیش ۶۸۰٫۰۰۰ ریالی در انتظار تأیید» |
| فیش تأیید شد | زنگ برای پرداخت‌کننده | «فیش شما تأیید شد؛ بدهی به‌روز شد» |
| عبور از سقف | زنگ + ایمیل (اگر فعال) | «۹۰٪ بودجهٔ خوراک این ماه مصرف شد» |
| هدف پس‌انداز رسید | زنگ | «به هدف «سفر» رسیدید» |
| نقش شما عوض شد | زنگ | «نقش شما در گروه همکاران به مادرخرج تغییر کرد» |

هر اعلان به مقصد دقیق لینک می‌دهد، نه به صفحهٔ اول.

## ۱۱. دسترس‌پذیری و موبایل

- همهٔ جدول‌های جدید در موبایل به کارت تبدیل می‌شوند (الگوی موجود `responsive-table`).
- ماتریس دفتر روزانه در موبایل: انتخاب عضو → فهرست تیک، جای اسکرول افقی.
- تمرکز صفحه‌کلید روی هر drawer قفل می‌شود و با `Esc` برمی‌گردد.
- هر نمودار یک جدول متنی معادل با `aria-describedby` دارد.
- کنتراست و اندازهٔ لمسی طبق [DESIGN-SYSTEM.md](../DESIGN-SYSTEM.md).
- تست‌های موجود `a11y-shell.spec.ts` و `keyboard-journey.spec.ts` برای مسیرهای جدید گسترش می‌یابند.
- `visual-shell.spec.ts` برای هر صفحهٔ جدید یک snapshot می‌گیرد.

## ۱۲. دستور جست‌وجو (command palette)

آیتم‌های جدید به palette موجود اضافه می‌شوند تا کاربر بی‌نیاز از پیمایش منو باشد:
`کاتالوگ` · `افزودن قلم` · `صورتحساب من` · `پرداخت بدهی` · `فیش‌های در انتظار` · `تنخواه` · `دوستان` · `یافتن کاربر` · `مالی من` · `هدف پس‌انداز` · `تحلیل ماه`

هر آیتم فقط وقتی در palette هست که کاربر واقعاً به آن دسترسی داشته باشد.
