# S10-A4 — اتمیک بودن post خرج / confirm تسویه با journal



| فیلد | مقدار |

|------|--------|

| بسته | A4 (موج الف) |

| شناسه‌ها | S10-13 · S10-14 |

| وضعیت | انجام‌شده |

| وابستگی | A1 · A2 · A3 |



## ۱. ایده / مسئله



| ID | شکاف | شواهد |

|----|------|--------|

| S10-13 | status به `posted`/`confirmed` در یک txn و journal در txn جدا → شکست mid-flight | `expenses.service.ts` · `settlements.service.ts` |

| S10-14 | تست regression برای شکست journal پس از commit وضعیت وجود نداشت | فقط happy-path |



## ۲. طراحی



- **Postgres:** یک `withTenantContext` بیرونی؛ storeها `tx` اختیاری می‌گیرند.

- **Memory:** پس از شکست journal، `compensateStatus` وضعیت را برمی‌گرداند.

- Audit/notify بیرون از txn پول.

- Company budget spend داخل همان txn وقتی postgres است.

- Reverse خرج posted + journal نیز اتمیک.



## ۳. تصمیم



قفل‌شده طبق بالا — بدون outbox در این بسته (R10-03 جدا).
